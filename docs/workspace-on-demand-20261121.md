# 按需載入、後端分頁與首頁待辦

基準 05fc339，使用者只選擇第 1、3、4 項；薪資二次驗證不在本次範圍，登入頁保持原樣。

## 本次交付

- 後台從整個 workspace 改為白名單 view 查詢；每個功能只讀自己的資料表與必要依賴。舊 scope=all／workspace 仍相容，避免已開啟的舊瀏覽器突然缺資料。局部結果以合併更新，不清空其他功能的快取；同功能請求合併並防止較慢的導航覆蓋最後一次點擊。
- 車輛、保險、保養等功能需要司機選單時，只讀姓名、手機、車商、狀態等必要資料。原始司機頭像約 2.78 MB，不再跟著每個輔助清單下載。駕駛管理及上線管理保留完整資料；driver／vehicle／vehicleFolder 編輯前另以 workspace_record 讀取完整紀錄，讀取失敗即不開編輯，不把精簡清單當完整資料儲存。
- partial_tables 明確標記精簡資料，前端逐 ID 合併、保留未提供欄位，並使駕駛完整頁快取失效。文件、駕駛歷程、登入與保險欄位不會被精簡結果清空。
- 費用改成 payment_page RPC：資料庫執行文字／車商／類型／狀態／日期篩選、穩定排序與每頁 50 筆。總筆數、待確認筆數與金額依全部符合條件資料計算，不只當頁。姓名電話目錄獨立保留五分鐘；搜尋與換頁不下載完整駕駛資料。新增／編輯／刪除使頁面快取失效，保留目前篩選；修正可選日期空字串轉 null，避免新增後無法查詢。
- 新增 assets/admin-payments.js，費用列表、篩選、分頁及表單抽離主程式；新增 assets/office-todos.js，待辦摘要查詢與呈現獨立。報班、檢查、點數／用品、ZIP、看板管理等既有模組改成進頁才下載。共用主程式仍保留，這是首批拆分，不宣稱整個大型主檔已拆完。
- 首頁「待我處理」顯示保養完成待補工單、近七日／逾期保養排程、保險退回／報價審核／文件需求、未完成罰單。各組顯示總數與前五項，可直接前往相應功能。後端按當前角色權限組合查詢，未授權者連數字也不回傳。待辦不複製案件、不自動改狀態；當次進頁使用一分鐘快取，另有手動刷新。已繳待核對仍列為核對待辦，但不誤標繳款逾期。

## 新查詢及資料保護

- migration：20261121010000_workspace_read_queries.sql，以及完成日期改用台北日的 20261121020000_office_completion_timezone.sql，只新增 office_payment_page、office_todo_summary 兩個 STABLE／SECURITY INVOKER 唯讀函式及 grant，沒有修改／刪除任何業務資料。兩函式撤銷 public／anon／authenticated EXECUTE，只授 service_role；data-api 再驗證 admin 與功能權限。
- workspace_record 只允許 admin 查詢有權限的 drivers／vehicles，固定表白名單與 UUID 驗證；不接受任意 table／column／SQL。
- 正式發布前已備份 65 張 public 表、791 筆 Storage metadata；私人備份不提交 Git。沒有照片物件異動，所以未以 metadata 備份冒稱實體照片備份。
- 完整正式快照已在隔離 PGlite 建立並演練，65 表逐表原始資料雜湊一致；正式增量以 repeatable-read 交易加入同樣的資料雜湊保護，失敗即 rollback。未執行全歷史 db push 或回灌舊資料庫。
- 舊金額、含稅拆分、租借與駕駛分離、保養到工單流程、角色與公司隔離均沿用。

## 邊界與後續

- 其他模組仍有「功能內整批載入」，下一批可逐一改成伺服器分頁／明細 API；此次未為了省流量截斷使用者要求全部顯示的保養／怠速資料。
- 駕駛管理本人需要看頭像時仍保留原始照片；將舊內嵌頭像轉私人 R2 縮圖應另立可回復的搬移流程，不能直接清掉資料庫欄位。
- 主程式進一步拆分應持續按領域分批做；此次沒有換框架或重建系統。
- 待辦目前按可處理的功能權限分組，沒有臆造案件負責人欄位；預測尚未安排的保養需要下一階段整合預測摘要。現有派趟／航班／看板更新頻率維持。
- 回退前端或 data-api 時可保留新增唯讀函式；不可用舊備份覆蓋正式期間新資料。

# 訂購便當、保養判讀、班表與選單排序

2026-11-25（Asia/Taipei）。既有 Cloudflare＋雲端 Supabase 系統增量發布，沒有搬入本機資料。

## 訂購便當

- 使用者確認限所有啟用內部員工；不對司機／車商／停用員工開放，不需另授個人功能權限。後端每次查核員工是否啟用及正式姓名。
- 側欄員工辦公室新增分頁。每人可建立店家／菜單、發起一次訂購、指定台灣時間截止。店家由建立者及最高管理員編輯；任何員工可使用別人建立的店家開團。
- 開團前須確認本次門市價格；以 shop_revision 確認菜單未在核價期間異動。本團凍結店家名稱、菜單與價格，後續改店家不影響舊團。
- 各人登記數量、單品備註及整單備註；截止前可改／取消自己的餐點。伺服器使用資料庫時間鎖單，不能調前端時鐘繞過。發起人／最高管理員可提前截止或取消團，明細保留。
- 後端以本團菜單重算價格，使用整數分計算金額，拒絕偽造單價、其他團餐點、重複品項、錯誤數量及過期 revision。request_id 防未知成功後重試重複開團／存單；交易鎖避免截止與訂單寫入競態，audit 保留操作。
- 顯示品項數量合計、各人金額與全部備註，匯出 CSV 防公式注入。僅內部彙整，不會自動向店家下單或扣款。首頁列最近40團；未實作長期歷史分頁，資料仍留庫中。
- 目錄只讀店家摘要，點入店家才下載完整菜單；團明細按需查詢。不新增資料庫輪詢，截止顯示本機計時，重新整理由使用者觸發。
- 已建立八方雲集台中參考菜單。2026-11-25 查詢，品項參考官網 https://www.8way.com.tw/ ，中部價格來源 https://cpok.tw/49622 。官方訂購系統未取得可驗證的指定台中門市現場價；外送價不同，不能宣稱是已核實的最新門市價格。使用者同意先建立可編輯參考菜單，開團前核價；種子只新增新表紀錄，不覆寫既有店家或業務資料。

## 保養管理

「里程可疑」原本只是資料一致性檢查，不代表必須保養。現在顯示「資料待核對」，直接列來源日期／里程、對照日期／里程、倒退差額或不合理增量；未到、將到、已達保養里程及排程逾期分別呈現。缺少資料不能當作正常。

「只看需安排」與「資料待核對」分開，互斥切換，顯示各自台數與目前／全部台數，卡片保留詳細原因；依使用者後續要求，完整表格只留單一小型狀態按鈕（需安排紅色驚嘆號、待核對黃色驚嘆號、正常勾號），點擊才用對話框顯示保養／調胎原因，不撐高表格。前次已完成但待工單，不能遮住後續新到期保養。沒有平均日里程但有近期實測時，可依實測判斷是否達里程，明示實測日期且不捏造預計日期；未來加油日期另外標明。沿用合理里程與30天預測限制，不自動改掉原始紀錄／工單。

## 班表速度與換車

- 新增 driver_roster_page，一個 RPC 取得月份、司機區域、目前／預配車、休假、備註與排程，替代原先報班 RPC＋班表 RPC＋司機區域查詢。不逐司機執行 SECURITY DEFINER 查核。
- 按登入身分／月份記憶體快取20秒，最多12份；再次打開立即顯示。變更休假／備註、車輛、駕駛、車商、排程或完成上線時失效；台北日期跨日不沿用昨日快取。
- 已有 stamp 及 unchanged 回應，版本包括駕駛姓名／狀態／區域、車牌／指派、車商與月份規則 revision，避免新設定被舊快取長期蓋住。保留既有每分鐘小版本查詢與後端 CAS，不能用快取繞過權限。
- 自動換車備註只呈現車牌數字；原車牌資料、標題、車輛管理與指派 ID 均保留，沒有把正式車牌刪掉英文。原右鍵、Excel 剪貼、休假審核與單一垂直捲動不變。

## 排序管理

最高管理員可改全公司左側選單分組名稱、分組順序、功能順序、功能所屬分組及選單顯示文字；支援拖曳及按鈕，儲存後跨帳號保留，其他已開畫面重新整理讀取。這是導航設定，不是員工部門／職稱與授權設定。

每個功能必須完整保留一次，後端鍵值白名單、防重複／漏項、revision CAS 及 audit；新功能補入未配置區，不能被舊設定吞掉。仍按原角色／個人／部門有效權限過濾，不因移動或改名開放功能。普通員工不能存全公司設定。

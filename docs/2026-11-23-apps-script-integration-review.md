# 亞菲得行控平台整合評估

檢查日期：2026-11-23（Asia/Taipei）。本次僅讀取使用者提供的公開部署頁面與該頁正常載入的前端程式；未輸入通行碼、未讀取受保護業務資料、未執行匯入／寄信／設定／正式上線操作。原始頁面及程式快照留在忽略的私人檢查目錄，不提交公開 Repository。

## 結論與可驗證範圍

可以逐步搬進目前 HEYCAR。應沿用現有登入、後端授權及司機／車輛／廠商主檔，將外部平台的派單、原檔、憑證、帳務邏輯改寫成現有系統的模組。直接 iframe 嵌入會保留兩套登入、權限、主檔與資料狀態，不能算完成整合。

實際讀到的頁面標題為「亞菲得行控平台」，導覽顯示 v10；頁面包含首頁、匯入訂單、派趟、回填／異動、原檔回傳、司機通知、出租單、帳務、司機車輛、設定。初始頁會載入 getAppJsBundle；已檢視正常載入後的前端程式。以下表示前端已有操作介面／呼叫，不代表已用真實資料驗證其後端執行結果。

| 外部功能 | 已看到的前端操作／介面 | HEYCAR 整合方式 |
|---|---|---|
| 訂單匯入 | 平台 Excel、格上簡訊／加派、文字貼上、多檔比對新增及變更 | 加入既有派趟中心匯入流程；保留來源單號／平台／原始列，先預覽差異及排除重複 |
| 派趟與異動 | 派趟表、派趟日曆、司機／車商指派、回填與取消 | 延伸 dispatch_orders，沿用目前車商隔離與離職司機限制，不另建重複司機主檔 |
| 原檔與車趟表 | 原檔下載／回傳、車商車趟表、回傳後異動 | 新增原檔版本、回傳批次及比對紀錄；沿用私人 R2 附件，保留原件 |
| 司機通知 | 通知內容、通知發送標記 | 整合現有司機訊息／LINE 授權及通知紀錄；發送前確認收件人，未知成功不得重送 |
| 出租單／憑證 | 和雲出租單、格上三聯單、缺漏清單、憑證核對／備份 | 與訂單關聯的獨立憑證模組，保留 PDF／圖片及版本，不寫成車輛工單 |
| 帳務 | 平台對帳、車商月帳、月結檢查及鎖定、營運總表 | 新增明確權限的帳務工作區，不能直接把現有費用「已確認」改作「已收款」；月結採交易／鎖定／審計 |
| 司機／車輛與證件 | 主檔對照、證件分類／掃描／批次處理、到期資訊 | 先建立舊 ID 對照；差異逐欄核對，局部更新，不覆蓋現有駕駛歷程、保單及其他文件 |
| Google 作業 | 前端呼叫郵件搜尋、PDF、Google 檔案與營運總表同步等 API | 需要原 .gs 後端、Drive／Gmail 授權與觸發器設定，改為伺服器端 Secret／OAuth；不能靠前端直接搬移 |

前端對帳程式特別區分和雲、格上的欄名與實收來源，例如和雲使用「外車對帳」欄；整合時不能把不同平台的任意金額欄當應收。確切計價、加派、取消、補單、日期切點及月結規則，仍須連同後端與樣本逐項核對。

## 完整搬移前需要的資料

1. Apps Script 專案原始碼：全部 .gs、HTML／JS 與 appsscript.json；前端部署頁不能取得伺服器端實作。
2. 使用中的 Google 試算表：分頁、標題欄、公式、關聯鍵、少量去識別化範例，以及每張表筆數。不必在聊天貼帳密或金鑰。
3. Drive 資料夾用途、原檔／模板／PDF／備份路徑對應及分享權限；授權後先只讀盤點，不搬動或刪除原件。
4. Gmail 搜尋條件、自動抓單觸發器、寄信規則、帳號／授權所有者及重複處理標記；瀏覽器能開網頁不表示 HEYCAR 已取得 Gmail 授權。
5. 各平台正常、取消、加派、回填、月底跨月等測試案例與輸出樣本，確認每個功能都有驗收對應。

## 建議階段與驗收

1. 只讀盤點與功能矩陣：列出所有原功能、資料表、Google API、匯出／列印樣板及角色；確認完整清單後再開發。
2. 建立測試匯入與 ID 對照：車商以現有廠商 ID 為主，車輛車牌正規化，司機用已確認對照，歧義人工核對，不猜測合併。
3. 先接訂單／派單／回填／原檔，再接出租單與通知，最後接對帳／月結／Google 自動化。逐項沿用目前 UI 元件及權限管理。
4. 平行驗算：同一批來源檔核對訂單筆數、金額、車商拆分、缺漏憑證、匯出結果及月結；暫不寄信、不回寫原檔、不啟用正式觸發器。
5. 驗收後才安排切換：保留來源 ID、匯入批次、版本與 audit；預先備份並有回退路徑，禁止整庫覆蓋 HEYCAR 正式資料。

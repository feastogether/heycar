# 下線管理、後台共用規範與班表查詢優化

## 功能

新增禮賓司機／下線管理。`driverOffboarding` 允許發起、明細與七項簽認；`driverOffboardingApprove` 另控制車輛部核准、照片審核、取消與結案，兩者都要具備。最高管理員可用，既有員工不自動全開新權限，可在員工管理授權。

流程：選司機、離職日及原因 → 車輛部同意 → 按離職日有效配車建立返還檢查 → 司機於車輛檢查拍攝十個基本角度、里程及不限張損傷照片／說明 → 車輛部照片通過 → 七項確認完成 → 確認返還並結案。離職當天23:59為期限，逾期仍允許補傳並標示；任務只對指定本人開放，即使原車商沒有一般檢查入口，也提供該待辦入口。

七項為離職日期、借貸、應付薪資、停車欠費、罰單欠費、維修、洗車費。每項保存確認日期、核對金額／說明、伺服器認證的填寫人與時間；無款項填0，未填不能視為0。這是核對紀錄，不自動扣薪、建立收款或清掉罰單。可補填背板、二代健保、停派、黑名單、退群與訪談。

核准不解除配車、不改司機狀態。只有結案交易會立即結束此人的有效歷程（end_at、returned_at、offboarding_id），更新目前使用人、離職日並停用本人登入／撤銷本人session；共同駕駛、其他人session、保單、文件及其餘歷程保留。車輛列表／卡片顯示最後使用紀錄；同日返還即排除即時指派，歷史日期仍保留。已結案返還歷程有資料庫保護，不能被後續編輯移除。

核准後配車被改動會拒絕結案並回滾，需核對後取消／重新發起，不能覆蓋新歷程；存在離職日以後待生效換車也會擋下。無配車時必須明確填無車返還原因，才允許無返還任務例外；不得猜車牌。取消只隱藏關聯檢查，不物理刪照片，已有核對／audit保留。日期核准後不可直接改，避免照片證據與日期失聯。

列印含退隊單、七項簽認、返還明細及照片，參照使用者提供的退隊Excel；九項車況勾選及本人／督導／副理簽名保留紙本填寫，不宣稱電子簽章。照片按需取得十分鐘私人簽名網址，列印前載入；不把私人照片公開。

## 既有功能修正

新增司機的空白ID／姓名不再匹配所有車輛，未儲存司機不顯示指派車。編輯車輛歷程保留原列未知metadata，避免表單重組掉返還標記。登入頁不改。

後台共用按鈕、標題操作列、篩選與彈出框規範見 `ADMIN_UI_GUIDELINES.md`；司機介面獨立。班表重寫driver_vehicle_links／driver_roster_vehicles，只解析必要指派欄位一次，name fallback僅唯一姓名、ID優先；stamp不序列化整台車的文件。僅班表相關函式停用JIT，不放寬全庫timeout。既有日期生效換車、region、月份規則、剪貼、排序與快取隔離保留。

## 程式與資料庫

- 前端 `assets/driver-offboarding.js`／`.css`，按需載入；通用後台 `assets/admin-ui.css`。
- 專用handler `supabase/functions/data-api/driver-offboarding.mjs`，入口明確action routing及權限；新表禁止generic API。
- 增量 `20261126030000_roster_assignment_query.sql`、`20261126040000_driver_offboarding.sql`。新case／vehicle-link／audit三表，RLS、非公開RPC、版本CAS與request_id防重複。照片沿用私人R2／舊Storage混合讀取，沒有新bucket或密鑰。
- 只套用兩個當次增量，不重跑歷史seed、不回灌任何本機資料。
